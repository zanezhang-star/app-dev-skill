# 任务路由矩阵

选择当前证据支持的最轻通道；仅在范围或风险变化时重新分级。

| 信号 | Fast | Standard | Controlled |
|---|---|---|---|
| 范围 | 单一局部行为 | 多文件/模块或接口、配置变化 | 跨系统或广泛重设计 |
| 需求 | 明确 | 基本明确，需少量 AC | 模糊或关键决策多 |
| 可逆性 | 容易 | 中等 | 困难或破坏性 |
| 数据/权限/安全 | 无 | 沿用既有低风险模式 | schema/迁移、认证授权、密钥或敏感数据 |
| 依赖 | 无或既有本地依赖 | 重要内部依赖 | 新外部 API、基础设施或跨项目依赖 |
| 默认执行 | 当前 Agent | 当前 Agent，角色按需 | 明确合同、Gate 和角色 |

## Fast 禁入条件

任一项成立时不得使用 Fast：

- 数据库/schema 迁移或生产数据修改；
- 认证、授权、权限、隐私、安全、密钥或敏感数据；
- 外部 API/集成、基础设施、部署或破坏性操作；
- 会改变实现的业务语义尚未确定；
- 多模块且回归面无法快速界定；
- 用户明确要求正式方案、独立审查或阶段化交付。

## 角色选择

只有存在具体待解决问题时才增加角色。

| 待解决问题 | 角色 |
|---|---|
| 用户可见行为或验收条件不清 | Product |
| 关键架构、数据或集成取舍 | Architect |
| 实现 | Developer / 当前 Agent |
| 需要独立检查需求、风险或证据 | Quality |

Fast 只用 1 个角色。Standard 包含当前 Agent 在内最多 3 个角色。Controlled 不设固定上限，但每个角色必须有不同的明确产出。

## 验证深度

- Fast：覆盖变化行为的窄测试、scoped diff review、适用时 `git diff --check`。
- Standard：focused tests，加覆盖直接变化链的最小广测。
- Controlled：读取 `references/verification-preflight-and-risk-matrix.md`，从合同和风险推导 Gate。

仅任务资料或文档变化不触发全量测试；可执行代码、配置、依赖、合同行为或测试逻辑变化时，重跑受影响检查。

## 状态语义矩阵触发

多数据源、多阶段、降级、默认/空/零/历史值、权限差异或可重试错误会使状态合并存在业务风险：Fast 应升级，Standard/Controlled 应按 `references/feedback-and-verification.md` 建立并审查最小状态语义矩阵。
