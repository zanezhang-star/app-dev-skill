# 续跑协议

仅在继续中断、跨会话或交接的 app-dev 任务时读取。目标是恢复最小充分上下文，而不是重放全流程。

## 1. 锁定任务

- 先确认项目根、当前分支、HEAD、Git 状态和 scoped diff。
- 用户给出 task ID、task brief 或路径时，验证其位于项目内后使用。不为找任务扫描整个仓库。
- 存在多个可续跑任务且无法由分支、diff 或用户请求唯一确定时，只询问一个选择问题，不猜测。
- Fast 无持久化任务时，仅由原请求、当前 diff、相关代码和测试重建最小工作集。

## 2. 检查新鲜度

- 重读与当前范围直接相关的项目规则、验收条件、未决项和最后验证证据。
- Standard 先核对 task brief；只有实际委派时才检查 lightweight Packet。Packet 过期时重新生成并局部复核。
- Controlled 先核对 `status.yaml`、批准合同、预检和下一个实际角色的 Packet；按 `context-routing.md` 运行 freshness 检查。
- 已通过的证据只在直接变化链已改变、证据无法核实或新风险使其失效时重跑。

## 3. 恢复执行

- 沿用原通道；仅在新证据或用户指定时切换，并遵守主协议的安全降级底线。
- 用一行播报：`继续使用 app-dev · <Fast|Standard|Controlled>：<恢复点与下一步>`。
- 从第一个未完成验收项或失效 Gate 继续；不重新运行 `init_task.py`，除非确认原任务不可恢复。
- 交付时同步任务状态或 task brief，并汇报复用的证据、新跑的检查和仍未验证的限制。
